### Статуси

✅ готово · 🟡 частково (є заготовка або UI на моках) · ⬜ не розпочато · ❓ потрібне рішення або дизайн

### Процес (git flow)

- `main` — тільки релізи, напряму не чіпаємо.
- `dev` — інтеграційна гілка.
- Кожна задача робиться в гілці від `dev`: `feature/<ID>-<коротко>`, наприклад `feature/F-07-discard-modal`. PR відкриваємо в `dev`.
- Задачу можна закривати, коли виконані критерії приймання, проходять `pnpm typecheck` і `pnpm build`, а UI відповідає макету (світла й темна тема, десктоп і мобільний).

## Доменна модель (чернетка для B-задач)

```
User ──< Membership >── Household ──< Product ──< ProductEvent (write-off / cook)
                │                 ├──< ShoppingItem
                │                 ├──< Invite (email | code, TTL 7 днів)
                │                 └──< StorageZone (fresh / middle / door / freezer)
                └── role: OWNER | MEMBER
Recipe (згенерований або з каталогу) ──< RecipeIngredient (→ Product? / missing / substitute)
Notification (user, type, payload, readAt)
```

Ключові поля `Product`: `name`, `brand`, `category`, `zone`, `quantity`, `unit (g|kg|ml|l|pcs)`, `purchasedAt`, `expiresAt`, `openedAt`, `effectiveExpiresAt` (з урахуванням відкритої упаковки), `remindBeforeDays (1|2|3|7)`, `addedBy`, `status (ACTIVE|CONSUMED|WASTED)`.
